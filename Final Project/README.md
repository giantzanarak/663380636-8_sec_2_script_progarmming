## 1. ภาพรวมโปรเจกต์

**HOW DO YOU FISH** คือเกมจำลองการตกปลาแบบ Desktop Application เขียนด้วย Python และ Tkinter
ปลาทุกตัวในเกมเป็น**ชนิดปลาจริง**ที่ดึงมาจาก Public API

**ปัญหาที่ต้องการแก้** — ข้อมูลปลาจริงมีอยู่และเข้าถึงได้ฟรี แต่ถูกเก็บเป็นตารางและรหัสวิชาการ
ไม่มีรูปแบบการนำเสนอที่ทำให้คนทั่วไปอยากเปิดดูซ้ำ

**แนวทางแก้** — ทำเป็นเกม ผู้เล่นเลือกแหล่งน้ำ ตกปลาด้วยมินิเกม แล้วนำปลาไปขายเพื่ออัปเกรดอุปกรณ์
ทุกครั้งที่จับได้จะเห็นชื่อสามัญ ชื่อวิทยาศาสตร์ และกลุ่มของปลาชนิดนั้น
ความรู้เรื่องสายพันธุ์จึงถูกส่งถึงผู้เล่นโดยไม่รู้ตัว

**วงจรการเล่น:** เลือกสถานที่ → ตกปลา (มินิเกม QTE) → ขายและอัปเกรด → กลับไปตกปลาที่ยากขึ้น

**Domain:** Data Analysis & Management — ดึงข้อมูลผ่าน API · ค้นหา กรอง เรียงลำดับ ·
สรุปสถิติ · สะสมประวัติไว้วิเคราะห์ย้อนหลัง

## 3. โครงสร้างระบบ

โค้ดแบ่งเป็นชั้น แต่ละชั้นรู้จักเฉพาะชั้นที่อยู่ถัดลงไป จึงเปลี่ยนชั้นหนึ่งได้โดยไม่กระทบชั้นอื่น

| ชั้น | ไฟล์หลัก | หน้าที่ |
|---|---|---|
| Presentation | `src/gui/app.py` · `src/gui/pages/` · `src/ui.py` · `src/cli.py` | วาดหน้าจอ รับการกด |
| Application | `src/gui/presenter.py` | ตัดสินใจแทนหน้าจอ เช่น ปุ่มไหนกดได้ ข้อความอะไรต้องแสดง |
| Domain | `src/game_state.py` · `src/fish.py` · `src/minigame.py` · `src/difficulty.py` · `src/ai_fishing.py` | กฎของเกมทั้งหมด |
| Validation | `src/validators.py` | ตรวจอินพุตของผู้เล่น |
| Data Access | `src/save_manager.py` · `src/catch_log.py` | อ่านและเขียนไฟล์ |
| Integration | `src/worms_api.py` · `src/openfisheries_api.py` · `src/fish_api.py` · `src/update_checker.py` | คุยกับบริการภายนอก |

และสิ่งที่ผลไม่แน่นอน เช่น เครือข่าย เวลา และการสุ่ม ถูก**ฉีดเข้ามาจากภายนอก**
เทสต์จึงใช้ของปลอมแทนได้ทั้งหมด

## 4. API ที่ใช้

| API | ใช้ทำอะไร | ถ้าเรียกไม่สำเร็จ |
|---|---|---|
| **WoRMS** (World Register of Marine Species) | ชนิดปลาจริง ชื่อวิทยาศาสตร์ และแหล่งน้ำที่พบ | ใช้ข้อมูลสำรองในเครื่อง 90 ชนิด |
| **Open Fisheries** | ชื่อสามัญภาษาอังกฤษของปลา | แสดงชื่อวิทยาศาสตร์แทน เกมเล่นต่อได้ |
| **Google Gemini** *(ไม่บังคับ)* | ตั้งชื่อและเลือกประเภทเควสต์ประจำวัน | สุ่มเควสต์ในเครื่องแทน |
| **GitHub Releases** | ตรวจว่ามีเกมเวอร์ชันใหม่หรือไม่ | ไม่แจ้งเตือน เกมเล่นได้ตามปกติ |

หลักที่ใช้กับทุก API คือ **"ของเสริมต้องล้มเหลวได้"** — ไม่มีเน็ตหรือบริการล่ม เกมต้องเล่นต่อได้เสมอ

## 6. งานที่ผู้จัดทำรับผิดชอบ

| สปรินต์ | บทบาท |
|---|---|
| Sprint 1 — Front-End (Lab 12) | Coder |
| Sprint 2 — Back-End (Lab 13) | Coder |
| Sprint 3 — Full-Stack (Lab 14) | Planner |
| Final Sprint — DevOps & AI (Lab 15) | Debugger / QA |

### Sprint 1 — Coder (ชั้นแสดงผลและการไหลของเมนู)

- พัฒนา `src/ui.py` เป็นชั้นแสดงผลที่**มีแต่ `print()` ล้วน** ไม่มีการคำนวณปน
  สปรินต์ถัดไปจึงเปลี่ยนเป็น GUI ได้โดยไม่แตะตรรกะ
- พัฒนา `src/cli.py` คุมการไหลของเมนูทั้ง 5 หน้าจอ และดัก `EOFError` โปรแกรมจึงไม่พังเมื่อป้อนข้อมูลผ่าน pipe
- เขียน `main.py` บังคับ UTF-8 บน Windows Console ให้ภาษาไทยไม่เพี้ยน

### Sprint 2 — Coder (ชั้นตรรกะเกม)

- แยกตรรกะปลาและกฎราคาเป็นคลาส `Fish` ใน `src/fish.py` รับ `rng` จากภายนอก เทสต์จึงกำหนดผลสุ่มได้
- พัฒนา `src/game_state.py` คุมเงิน กระเป๋า และการอัปเกรด พร้อมระบบ **ค้นหา · กรอง · เรียงลำดับ**
- พัฒนา `src/minigame.py` คลาส `QTEMinigame` ที่**ฉีดนาฬิกาเข้ามาได้** เทสต์เรื่องหมดเวลาจึงไม่ต้องรอจริง
- แก้บั๊กการเรียงที่ทำลายข้อมูลเดิม — เปลี่ยนจาก `.sort()` เป็น `sorted()` ที่คืนลิสต์ใหม่

### Sprint 3 — Planner

- ออกแบบ**ผังหน้าจอทั้ง 4 Frame** และเส้นทางสลับหน้า ก่อนเริ่มเขียนโค้ด ให้งานของ Coder แต่ละคนไม่ชนกัน
- เขียน **Definition of Done 13 ข้อ** ใน `PLAN.md`
- **ตัดสินใจไม่เขียน GUI ทับตรรกะเดิม** — ชั้น `game_state` · `minigame` · `fish_api` ต้องถูกเรียกใช้ตามเดิมทั้งหมด
- ส่งต่อแนวคิดนาฬิกาที่ฉีดเข้ามาได้จาก Sprint 2 การเปลี่ยนไปใช้ `root.after()` จึงไม่ต้องแก้ตรรกะ

### Final Sprint — Debugger / QA

- เขียน `tests/test_difficulty.py` **36 เคส** ยืนยันว่าระบบปรับความยาก**ไม่ทำให้เวลาต่ำกว่าขั้นต่ำ**ไม่ว่าผู้เล่นจะเก่งแค่ไหน
- ทดสอบว่าประวัติความยาก**ไม่ทำให้ไฟล์เซฟโตไม่สิ้นสุด** (เก็บสูงสุด 20 รอบ) และข้อมูลเสียต้องไม่ทำให้เกม crash
- เพิ่ม `TestFishingDifficulty` **6 เคส** ใน `test_gui_logic.py` — ต่อกับรอบการตกปลา และเล่นได้แม้ไม่มีตัวปรับความยาก
- ตรวจ **UML Class Diagram** (`docs/uml_class_diagram.md`) ให้ตรงกับโค้ดจริง และตรวจว่าตัวเลขทุกตัวในรายงานตรงกับผลรันจริง
- รวมเทสต์ที่ดูแลในสปรินต์นี้ **42 เคส** · coverage ชั้นตรรกะ 95%
